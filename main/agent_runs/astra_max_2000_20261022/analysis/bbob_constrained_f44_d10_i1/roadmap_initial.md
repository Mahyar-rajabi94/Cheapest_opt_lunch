# Initial decision: feasibility and scale survey

Minimize a deterministic scalar objective over 10 coordinates in [-5, 5]. There are three black-box inequalities; a real observation is feasible only when all returned constraints are <= 1e-10. The result is the best feasible observation. The hard total budget is 2,000 calls, including infeasible points and repeats. No prior observations are available. No smoothness, convexity, feasible volume, or objective identity is assumed. Only the public interface and optimizer code have been read.

The first step evaluates the box center, then 64 scrambled Sobol points over the full box. Implementation: supplied `src.optimizers.sobol_search.SobolSearch`, using SciPy 1.17.1 `qmc.Sobol`, dimension 10, scramble=True, seed=20261022; other Sobol defaults are inherited from that version (bits=None, optimization=None). NumPy is 2.4.6 and Python is 3.11.14. The center is a neutral reference and the power-of-two Sobol batch offers reproducible, broad coverage without a presumed feasible region. No penalty or objective/constraint scaling is needed for this sampling step. All observations, including infeasible ones, are retained separately from the sampler's objective-only history.

Maximum additional calls: **65**. Pause at cumulative evaluation **65**. This is enough for a first assessment of constraint signs, feasible proportion, objective range, and candidate starting points in ten dimensions while leaving almost all budget available for evidence-based decisions. This document specifies only this first step.

At the checkpoint inspect the feasible count, best feasible value and coordinates, the three constraint ranges, objective quantiles, and least-violating observations. Compare the center with the broad sample. Since evaluations are deterministic, repetitions are unnecessary for estimating noise. An evaluator error triggers an immediate stop with no retry; nonfinite outputs also trigger an early review. Otherwise finish this bounded survey before deciding again. A persistent Python process retains the single harness, observations, and optimizer state; every actual call is protected by both the current block limit and the total budget. Call `h.save()` at the checkpoint.
