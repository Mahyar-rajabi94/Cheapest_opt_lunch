# OPV emulator report

Generated by `train_emulator.py` from `opv_emulator_data.csv` (526 rows). The emulator is a random forest that plays the role of the experiment: it returns PCE (%) for any snapped 11-value input. No optimizer was run.

## Summary

- **Model:** scikit-learn `RandomForestRegressor(n_estimators=500, min_samples_leaf=3, max_features=0.33, random_state=0)`, trained on all 526 rows (scikit-learn 1.8.0).
- **Inputs:** the 11 search variables in original units, after HTL/ETL snapping. **Target:** PCE (%), to be maximized. Metadata columns are not used.
- **Accuracy:** cross-validated R2 0.48 (RMSE 2.24% PCE) on random held-out devices and 0.41 (RMSE 2.39%) on held-out donors.
- **Saved model:** `opv_emulator_rf.npz` (1.0 MB, 86,598 nodes), read by `emulator.py` with numpy only. Its predictions match scikit-learn's (see Export check).
- **Speed:** 0.13 ms per single query (scikit-learn: 34.1 ms).

## Usage

```python
from preprocess import prepare_query
from emulator import Emulator

em = Emulator()
q = prepare_query(x_unit)   # 11 values in [0, 1]: unscale, snap HTL/ETL, check constraints
pce = em.predict(q['x'])    # PCE (%); q['feasible'] says whether the constraints hold
```

`Emulator.predict` also takes an (n, 11) array and returns n values. Retrain with `python train_emulator.py`; the run is deterministic (`random_state=0`).

## Model selection

Seven models were compared with two 10-fold cross-validation schemes: random folds, and folds grouped by donor polymer (every device of a donor is held out together). The grouped scheme is closer to the benchmark, where optimizers reach donor energy levels that are not in the data. These numbers were measured once on the `*_unit` columns and are not recomputed by the script. Two further tanh ensemble settings scored lower and are omitted.

| Model | R2, random | RMSE, random | R2, by donor | RMSE, by donor | Objective shape |
|---|---|---|---|---|---|
| Random forest (500 trees, min_samples_leaf=2) | 0.456 | 2.290 | 0.391 | 2.422 | flat steps |
| Gradient boosting (HistGradientBoosting, defaults) | 0.480 | 2.240 | 0.358 | 2.488 | flat steps |
| Neural-net ensemble, 10 x ReLU MLP (64, 64) | 0.427 | 2.350 | 0.377 | 2.450 | continuous, kinks |
| Neural-net ensemble, 10 x tanh MLP (32, 32) | 0.359 | 2.486 | 0.321 | 2.558 | smooth |
| Gaussian process, Matern 3/2 ARD + noise | 0.404 | 2.397 | 0.260 | 2.671 | smooth |
| Gaussian process, RBF ARD + noise | 0.392 | 2.421 | 0.245 | 2.698 | smooth |
| Gaussian process, Matern 5/2 ARD + noise | 0.398 | 2.410 | 0.163 | 2.840 | smooth |

The random forest was chosen (decided with the user) because it is the most accurate on held-out donors. The cost is the objective's shape: a forest's output is piecewise constant, so it is flat almost everywhere (see Flatness below).

## Accuracy of the final model

| CV scheme | R2 | RMSE (% PCE) | MAE (% PCE) |
|---|---|---|---|
| Random 10-fold | 0.481 | 2.24 | 1.71 |
| 10-fold grouped by donor | 0.408 | 2.39 | 1.88 |

- For scale: PCE has standard deviation 3.11% across the 526 rows, and repeated devices differ by a median of 0.38% (max 2.09%). Most of the error is therefore not measurement noise. It comes from what the 11 inputs leave out, mainly molecular structure.
- In-sample fit on all 526 rows: R2 0.762, RMSE 1.51%. This is optimistic and only shows how closely the emulator reproduces the training devices.

## Export check

`emulator.py` evaluates the exported trees with numpy and is compared with scikit-learn's `predict`. The script stops if any difference exceeds 1e-09. Threshold points place one input exactly on a split value, which tests the `<=` rule and the float32 rounding scikit-learn applies to inputs.

| Points | n | max abs difference |
|---|---|---|

## Behaviour over the search space

20,000 uniform random proposals in [0, 1]^11, unscaled and snapped:

- 55.0% satisfy all six required constraints.
- Emulator PCE over the feasible ones: min 2.22%, median 6.50%, max 11.28%.
- Best feasible random proposal (original units): HOMO_D = -5.52, LUMO_D = -3.45, Eg_D = 1.9, HOMO_A = -5.66, LUMO_A = -4.1, Eg_A = 1.47, DA_ratio = 0.99, additive_conc = 0.686, anneal_temp = 33.3, HTL_energy = -4.7, ETL_energy = -4.18.
- Over the 450 feasible training devices, the emulator's maximum is 12.93% (observed maximum 14.29%). A forest averages training targets, so it never predicts above 15.71%, the highest PCE in the data.

## Limitations

- **Flat steps.** The objective is piecewise constant along every input, not only HTL and ETL.
- **Capped predictions.** The emulator cannot exceed 15.71%. Beyond the training data it carries the values at the edge of the data outward unchanged.
- **Moderate accuracy.** R2 is about 0.41 on held-out donors, so the emulator is a plausible stand-in for reality, not a faithful one. Benchmark conclusions are about optimizing this surface.
- **Pre-processing limitations still apply** (see `preprocessing_report.md`): unsupported HTL x ETL combinations, independent energy levels, and no structural information.
